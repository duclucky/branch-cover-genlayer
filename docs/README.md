## One-sentence product hook

Free only the GEN that no remaining protocol choice can need, while keeping
every activated conditional promise fully payable.

## Trust problem

The funder wants low contingent exposure while beneficiaries prefer broad fee
activation. Neither should choose the semantic table that lets collateral leave.
A backend or EVM can compute a maximum after someone supplies its inputs; that
alone cannot provide neutral replicated interpretation of natural-language
activation conditions. Validators own interpretation; code owns every amount,
recipient, feasible branch and settlement transition.

## Scope and non-goals

Two named beneficiaries, three branches, 1-2 GEN face per claim. All participants
ratify pure constitutive payment conditions and branch definitions. Controller
choice is the contractual trigger. No factual external completion, real-service
execution, legal debt, identity, actual data ownership or external consumer
integration is asserted. No fee, slash, debt ranking, tradeable token or app.

## Fingerprint and analogue/differentiation matrix


1. Trust problem: neutral interpretation of contingent exposure before a funder
   can unlock collateral while other parties retain future selection-fee claims.
2. Actors/adversary: actual funder prefers low exposure; two beneficiaries prefer
   broader activation; a fixed controller owns permanent scenario elimination
   and the eventual single choice. No competing executor slots or senior creditors.
3. Evidence class + authenticity mechanism: exact protocol-created contingent
   promises and finite branch definitions, authenticated origin plus both payees'
   complete definition assent and immutable domain/version/time binding; actual
   branch choice is a runtime-authorized state transition. No external work claim.
4. Consensus question: does each branch definition entail each claim's activation
   predicate, in all six expected cells, or is it excluded/unclear?
5. State machine: full-margin funding/assent -> immutable compiled liability table
   -> monotone feasible-set reduction with immediate safe excess -> single chosen
   branch settlement or bounded no-choice recovery -> own exits/zero closure.
6. Direct consequence: conserve collateral against the maximum of all remaining
   branch liabilities before choice; release only proven excess; later pay every
   activated face in full. No haircut, offset, coalition share, winner or permit.
7. Reuse surface: contingent book/claim/branch/matrix/margin and permanent-pruning/
   choice/credit/accounting interface for workflow reservation and budget adapters.

## State model

Stable IDs: ASCII book ID [A-Za-z0-9_-]{1,64}; C0/C1 and B0/B1/B2 fixed local
IDs scoped by book. Keys are book_id + ':' + entity ID, attempts indexed from1,
mask history from1. Full definition digest includes network ID, contract address,
version BC_V1, roles, predicates, faces, exact branch bytes and both deadlines.

Storage: @gl.storage.allow dataclasses Book, Claim, Branch, Cell, Attempt,
MaskRecord; str-keyed TreeMap collections; class-body collection annotations.
Money/counters/deadlines/masks bigint; no dict/list/int persistent slots. Attempt
cells use structured per-attempt Cell records, not raw JSON as canonical model.
Views may encode structured snapshots as JSON strings for interoperability.

DRAFT (partial funding) -> RATIFYING (full face sum) -> READY (both assents)
-> RETRYABLE (UNCLEAR/source failure, max3 attempts) or COMPILED (frozen complete
matrix). COMPILED -> pruned COMPILED -> SETTLED (one choice). Pending/compiled
expired -> EXPIRED. SETTLED/EXPIRED -> CLOSED only with zero reserve and credits.
Ratification duplicates are no-op only with exact digest before review deadline;
after READY both payees may repeat exact assent without altering state.

Any compiled matrix is frozen forever. No mutation of actors/predicates/branches,
no branching outside the menu, no regrowth, no recompile, no reopening terminal
state. Public get_matrix is unavailable until COMPILED/SETTLED/expired-compiled;
get_attempt always exposes any recorded attempt and its status safely.

## Temporal entrypoint rules / legal authorization

Canonical gl.message.datetime, timezone-aware UTC seconds. now < review_deadline
< choice_deadline <= now+7days at creation. top_up, ratify and compile check
now < review_deadline. Prune/choose check now < choice_deadline directly.
Recover checks now >= review_deadline for pending states, now >= choice_deadline
for COMPILED. Equality is expired; stale phase never bypasses the clock.
Withdraw and zero-liability close are genuinely independent of time. No user
can cancel a funded book before its applicable deadline, including funder.
Controller must be configured party; public prose/signature strings grant no role.

## Consensus design and consequence


Name: BranchCover. Prospective child/repo: `branch-cover` (currently absent).
Exactly one product contract owns conditional claims, branch state, margin,
credits and withdrawals. No consumer contract or user-facing app is necessary.

Exactly two named beneficiary claims and three immutable protocol branches in
V1. Each claim has a positive bounded whole-GEN face amount (demo: 2 GEN each),
a pure natural-language activation predicate, stable ID, beneficiary and version.
Every branch has a stable ID and bounded definition. Choosing a branch means
only that its exact definition was selected on this contract, not that a real
tool ran or its description is a proven statement about the world.

The funder authors the full book and initial deposit; total deposits must reach
the sum of face amounts before either named beneficiary can ratify the exact
book digest. The controller is fixed by that definition. It can be the funder
or a named agent; overlapping roles are explicit and do not establish independent
human operators. Funder and both beneficiaries must be distinct addresses.

Judgment fields: each expected cell `claim_id:branch_id` is exactly once
TRIGGERED, NOT_TRIGGERED or UNCLEAR. TRIGGERED requires the branch definition
to entail the predicate. NOT_TRIGGERED requires clear exclusion or a complete
declared operation list that excludes it. Optional, contradictory, unspecified
or unsupported facts are UNCLEAR. Actual external performance must never be
invented from the prose. All three-valued choices are consensus-critical.

The validator independently re-fetches any required fixed context and reruns
the substantive task, normalizes all expected IDs and classes, and compares
the complete semantic matrix plus its contract-derived liability vector. Prose
may differ. No comparison of raw JSON strings, answer shape alone, or model
confidence can establish agreement. A non-Return leader result is rejected.

Let P[j] = sum(face[i] for each TRIGGERED cell i:j). With feasible branch set S,
required reserve R(S) = max(P[j] for j in S). All arithmetic is exact GEN
base-unit bigint internally; all human amounts are GEN. No model-chosen amount,
payee, branch ID, coverage or settlement class is trusted.

Any UNCLEAR cell prevents compilation: no margin or payment right is released;
only a non-penalizing append-only RETRYABLE attempt can be recorded. A complete
invariant-valid matrix is immutable after compilation. The initial feasible
set is all three branches. Compilation credits only `actual_funding - R(S)`.
Only the fixed controller may prune to a nonempty subset of S or choose one
remaining branch. A removed branch can never be restored, including by funder,
beneficiaries, retries or a duplicate call. Pruning credits exactly
`old_reserve - R(new_set)`; choosing pays every triggered claim in full and
credits the unused reserve to the actual funder. No seniority/haircut or winner.

No-choice expiry returns remaining reserve to the actual funder. These are
conditional protocol fees; no unconditional external debt is extinguished.
Every credit remains withdrawable by its own owner regardless of book expiry.
Book closure requires terminal state, no locked reserve and no outstanding
book-local credits. Global and book-local accounting use maintained counters.

## Invariants and write-method safety matrix


I1: received = locked reserve + outstanding credits + withdrawn for each book
and globally. Credit/withdraw counters never go negative.
I2: after compilation, locked reserve >= P[j] for every remaining branch.
I3: the six-cell semantic matrix and all actors/amounts/conditions are frozen.
I4: feasible set only shrinks, never empties before choosing, never regrows.
I5: one choice or expiry, one deterministic allocation, own-credit debits only.
I6: no incomplete/unknown/extra/missing/duplicate/invalid cell can unlock GEN.
I7: a time-based public write checks transaction time itself before mutation.
I8: actor-controlled prose cannot redefine IDs, authority, amounts, destinations
or the selection event. Configuration and runtime sender own these facts.

Canonical views proposed: `get_book`, `get_claim`, `get_branch`, `get_matrix`,
`get_margin`, `get_attempt`, `get_credit`, `get_accounting`, `can_choose`.
No global last-result field or raw overwriteable JSON is canonical storage.

Transaction clock: the pinned runtime's verified `gl.message.datetime`, converted
to integer UTC seconds. Creation locks `now < review_deadline < choice_deadline`
with a bounded duration. Equality at a deadline is late. Deployed API spelling

## Consequence and accounting

Full valid matrix -> freeze table/mask7, reserve max, funder surplus credit.
UNCLEAR/source failure -> RETRYABLE only, reserve/credit/choice unchanged.
Prune -> nonempty subset, reserve max(newmask), exact excess credit.
Choice -> every TRIGGERED claim full fixed face credit, exact residual to funder.
Expiry -> remaining actual reserve to funder; never erase existing own credit.
Writes are provisional at accepted boundary; demos/integrators wait finalization
and successful execution before relying on credit or branch state. External EOA
value messages use @gl.evm.contract_interface, default finalized delivery;
parent finalization alone is never transfer proof. Debit own ledger first.
No automatic restoration of failed message credit: halt and reconcile child
receipt/native balance, retain evidence, do not blindly retry.
